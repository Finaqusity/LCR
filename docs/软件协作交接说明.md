# 软件协作交接说明（给队友的 AI Agent）

> 面向对象：接手本仓库软件工作的 **AI Agent**（以及给它们派活的人）。
> 目标：让一个新 Agent 在 20 分钟内能独立开工、独立验证、独立提交，不破坏已有结论、不和别人的改动打架。
> 本文与 `docs/软件架构.md`（v1.0，1862 行）配套；两者冲突时，**以本文的协作规则 + 架构文档的技术结论为准**。

## 2. 权威性规则（最重要，防止"好心改错"）

1. **技术结论以 `docs/软件架构.md` 为准**。`docs/硬件接口.md`、`README.md`、旧稿 `numbers.md`（本地草稿，不入库）里被 §14.1 列出的差异都**已作废**。如果你发现旧文档与架构文档不一致，**不要按旧文档改代码**，也不要"顺手修正"架构文档，先在 Issue/消息里指出。
2. 下列决策是**经过逐条核对/三路 review 的定稿，禁止回退**（细节见架构文档对应章节）：

| # | 定稿 | 错误写法（不要用） | 出处 |
|---|---|---|---|
| 1 | ADC 时钟 **21 MHz**（PCLK2/4） | 28 MHz（PCLK2/3 不存在） | §1.3-M1、§4.1 |
| 2 | 采样 **S=16（100 Hz/1 kHz/10 kHz）、S=12（100 kHz，N=1008）** | fs=16·f0 全场 | §1.3-M2、§5.1 |
| 3 | ADC 触发 **TIM2_TRGO，EXTSEL=0b0110**（32 位定时器） | TIM8 TRGO 0110（0110 是 TIM2；TIM8 是 16 位装不下） | §1.3-M3、§4.4 |
| 4 | 母公式 `Zx = −Zf_eff·(m1/m2)/α`（**除以 α**） | 乘 α（差 α²） | §6.2 |
| 5 | 校准 = **α + 开路 + 双负载两点法**；**不做短路校准**（`CAL S` 报 ERR 9） | 短路校准降到 5 mVrms | §7.4 |
| 6 | 类型判据 **\|φ\|<5.7°** 为 R；电容 φ 为负（−73°…−84° 是电解电容，不会被判成 R） | \|φ\|<10°、把 D 角当 φ | §6.5、§14.1-D9 |
| 7 | 1 MΩ 档 **≤10 kHz（且仅校准后），100 kHz 禁止** | 1 MΩ 全频段可用 | §6.3、§6.4 |
| 8 | 10 µH@100 kHz **仅典型件可行**（ρ=1.59 超 10 Ω 档 ρ_max=1.4）→ AWD + 实板实测裁决，否则报 HEADROOM | 视 10 µH 为"合法" | §6.4、§12-R14 |
| 9 | Flash：**代码区 256 KB**（0x08000000–0x0803FFFF）+ **校准区 sector6+sector7 双扇区各 128 KB** | 代码 384/512 KB；校准只放 0x0807F000 一页 | §7.6、§8.2 |
| 10 | F4 ADC **没有** 软件自校准位（无 CAL/RSTCAL），只需 ADON=1 后等 tSTAB | 写"上电 ADC 校准流程" | §4.4、§14.1-D5 |
| 11 | 非 10 kΩ 档需要 **目标档 + K48 两只继电器**（约 42 mA） | "同一时刻只允许一只"（字面理解） | §4.3、§14.1-D14 |
| 12 | 继电器/GPIO 复位后是 **Hi-Z**，固件最早期必须把 PD0–PD6 配成输出低 | 认为复位态是"全低" | §4.7、§12-R3 |
| 13 | 采样缓冲必须在 **SRAM**（`.dma_buf`），**不能进 CCM**；栈也不搬 CCM | 把 DMA 缓冲放 CCM | §3.1、§8.1 |
| 14 | 串口协议中 `CAL S` 明确返回 `ERR 9 CAL_S_UNSUPPORTED`，不能静默成功 | 假装支持短路校准 | §8.5、§13.4 |
| 15 | 100 µH@10 kHz 不采用（\|Z\| 仅 6.3 Ω），L 优先 100 kHz | 按旧表选频 | §6.3、§6.7 |

3. **未确认的硬件事实不能编造**（12 项：短路口径、VR1/Cc 实际值、K 位号映射、ULN2803 COM/续流、SPI mode1/2、OLED 连接器、CH340 型号、NRST 按键、M3 孔、TP2、G6K 寿命、实物与脚本一致性）。这些在架构文档 §12 末尾"待硬件确认清单"里，遇到时**用保守实现 + 运行时探测 + 文档标注 TODO(确认项编号)**，不要猜死。
4. 改动技术数值（采样率、块长、时序、误差预算）时，必须用 `tools/verify/budget.py` 重算（跑一遍，断言全过才算数），并同步更新架构文档 §5/§9/§14.1；不允许"拍脑袋写个数"。

## 3. 工具链与验证命令

工具链**不在 PATH**，命令固定为：

**VS Code（推荐日常入口）**：仓库已提交共享配置（`.vscode/settings.json`、`tasks.json`、`launch.json`、`c_cpp_properties.json`、`extensions.json`）。装扩展 `ms-vscode.cpptools`、`ms-vscode.cmake-tools`、`marus25.cortex-debug` 后：`Ctrl+Shift+B` 编译（默认 `build (Debug)`，另有 Release/clean/flash 任务），`F5` 用 pyOCD + Cortex-Debug 下载并断点。先编译一次，IntelliSense 才有 `firmware/build/compile_commands.json` 可用。

```powershell
# 编译（Debug）：产物 firmware/build/lcr-fw.elf/.hex/.bin
powershell -ExecutionPolicy Bypass -File tools\build.ps1
# 编译 Release
powershell -ExecutionPolicy Bypass -File tools\build.ps1 -Release
# 清理重建
powershell -ExecutionPolicy Bypass -File tools\build.ps1 -Clean
# 烧录 + 复位（需要 DAPmini CMSIS-DAP 接上）
powershell -ExecutionPolicy Bypass -File tools\flash.ps1
# 串口监视（115200 8N1；脚本自带 python 查找，绕开 Windows Store 别名）
powershell -ExecutionPolicy Bypass -File tools\monitor.ps1 --list
powershell -ExecutionPolicy Bypass -File tools\monitor.ps1 --port COM5
# CubeMX：检查安装 / GUI 打开 .ioc / 从已配好的 .ioc headless 生成参考工程
powershell -ExecutionPolicy Bypass -File tools\cubemx.ps1
powershell -ExecutionPolicy Bypass -File tools\cubemx.ps1 -Open 'D:\Tools\lcr-cubemx\lcr.ioc'
powershell -ExecutionPolicy Bypass -File tools\cubemx.ps1 -Ioc 'D:\Tools\lcr-cubemx\lcr.ioc' -OutDir 'D:\Tools\lcr-cubemx\out'
```

> CubeMX 只作“配置仪表盘 / 参考代码对照”，**不要**把生成代码加进产品构建；用法与三处实测限制（纯 ASCII 路径、外设只能在 GUI 配、时钟不自洽会弹模态框）见 `docs/开发环境.md` §6.1.1。

> 不要直接敲 `python tools\monitor.py`：系统 PATH 里的 `python` 是 Microsoft Store 占位别名（报 "Python was not found"）。要用 Python 时调用真实解释器 `C:\Users\Finaqusity\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe`（带 numpy）。

关键绝对路径（换机器时按 `docs/开发环境.md` 重配）：

| 工具 | 路径 |
|---|---|
| arm-none-eabi-gcc 14.2.1 | `D:\Tools\embedded\arm-gcc-14.2\bin` |
| cmake 4.4.4 / ninja 1.13.2 / pyocd 0.46.1 / pyserial / python 3.12.14 | `C:\Users\Finaqusity\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\Scripts`（python 本体在其上一级） |
| VS Code 1.143.1 + Cortex-Debug 1.12.1 | `D:\Microsoft VS Code\bin\code.cmd`；配置已入库 |
| git | `D:\Git\cmd\git.exe` |

**合并门槛（Definition of Done）**：
- `tools\build.ps1` 与 `-Release` **都 exit 0**，且**新增 0 个编译告警**（现有 0 warning 基线要保持）；
- 新增/修改的算法有离线金标准或用例（本机**没有 host 编译器**，用 Python + numpy 生成 `test/vectors/*.h`，板上 `test.c` 串口比对，见架构文档 §10.2/§8.5）；
- 改动 C API 时必须同步架构文档 §3.4（见 §7 纪律）；
- 有硬件时：烧录 → 串口自检 → 记录 `SELFTEST` 输出；无硬件时：明确标注"未上板验证"，并列出待验证清单。

构建/环境已知坑（踩过，别重复）：
- 中文路径：POST_BUILD 的 objcopy 必须用相对文件名 `$<TARGET_FILE_NAME:lcr-fw>`；ELF 由 `set_target_properties(... SUFFIX ".elf")` 生出 `lcr-fw.elf`，改输出名要同步 `.vscode/launch.json`、`tools/*.ps1` 与文档；
- 所有 `.ps1` 必须是 **UTF-8 with BOM**；PowerShell 里 `-DCMAKE_BUILD_TYPE=$gen` 要整段引号；
- CMake 必须 `set(CMAKE_TRY_COMPILE_TARGET_TYPE STATIC_LIBRARY)`；`CMAKE_TOOLCHAIN_FILE` 只在首次配置传；
- libc_nano 的 8 个系统调用（`_close/_fstat/_getpid/_isatty/_kill/_lseek/_read/_write`）未实现告警 → 加 `Core/Src/syscalls.c`；`LOAD segment with RWX` 告警 → `-Wl,--no-warn-rwx-segments`；
- `-u_printf_float` **故意不使用**（+10.1 KB 且 `%f` 会走 malloc）；数值输出用 `results.c` 定点格式化；
- pyocd 没探针时只能编译不能验证；`monitor.ps1` 的中文提示在 GBK 控制台可能乱码，不影响功能；
- Python 优先用上表依赖目录里的 3.12.14（带 numpy）；不要用 `C:\Users\...\.local` 下的另一份 python（无 numpy），也不要信 PATH 里的 `python`（Store 占位别名）。CMake 里需要时显式 `-DPython3_EXECUTABLE=...`。


写作用域纪律（多 Agent 并行时最重要）：
1. **一个文件同一时间只有一个 owner**。开工前在任务里写明"你要改的文件路径"，并在仓库根的 `docs/软件任务板.md`（或 GitHub Issue）里认领；冲突时后到者换文件或等。
2. 允许**只读**任意文件；写只写自己认领的路径。
3. 改动 `firmware/Core/Inc/*.h`（模块接口）、`CMakeLists.txt`、`.ld`、`docs/软件架构.md` 属于**跨模块变更**：必须先发消息给 Lead，且在同一次提交里同步文档。
4. 笔记/实验脚本写 `DeepSeek/arch_notes/<你的名字>.md`，**不要写进 `docs/`**（docs 只放定稿交付物）。
5. 不要 `git add -f` 强推被忽略的文件；不要提交 `firmware/build/`、`*.elf/.hex/.bin/.map`、`DeepSeek/`、`_ds/`。

## 5. GitHub 协作流程（本仓库无 CI，靠本地门槛）

远端 `origin` = `https://github.com/Finaqusity/LCR.git`（已配置，公开仓库）。日常流程：`git pull --rebase` → 提交 → `git push`；首次拉取直接 `git clone https://github.com/Finaqusity/LCR.git`。**不要擅自把分支从 `master` 改成 `main`**，除非全员统一。

日常循环：

```powershell
$g = "D:\Git\cmd\git.exe"
& $g pull --rebase                 # 开工先拉
# ...改代码 + 本地 build 通过...
& $g status                        # 只 add 自己该提交的文件
& $g add firmware/Core/Src/adc.c firmware/Core/Inc/adc.h
& $g commit -m "feat(adc): TIM2_TRGO 触发 + 双 ADC 同步 + DMA 循环"
& $g push
```

硬性规则（AI Agent 尤其容易犯）：
- **不 `push --force`、不 `rebase` 别人的提交、不改写历史、不 `reset --hard` 已推送的分支**；
- 提交信息格式 `type(scope): 主题`，type ∈ `feat|fix|docs|chore|refactor|test`，scope 用模块名（`adc|dft|cal|meas|proto|ui|build|docs`），正文中文；
- 一个提交只做一件事；**每次提交前必须 build 通过**（无 CI，这是唯一闸门）；
- 拉取有冲突：按 `docs/GitHub同步.md` §4 解决；二进制文件（docx/pdf/png）冲突**不要合并**，找人类决定；
- 里程碑完成打 tag：`v0.2-m0`、`v0.3-m2`…（与架构文档 §11 对齐）。

Code review 约定（人类或 Lead Agent 执行）：
- 审 4 件事：是否符合架构 §3.4 契约、是否有越权改动（ld/CMake/旧结论）、是否破坏实时性（ISR 里做重活）、是否可验证（有金标准/自检）；
- 意见分 P0（阻塞，必须修）/P1（应该修）/P2（建议）；
- 修改他人代码先在自己的分支/文件上做，合并前经 owner 确认。

## 7. 接口契约纪律（跨模块协作的关键）

- 模块对外 API **已在架构文档 §3.4 冻结为 v1.0**：`board_*`、`dds_*`、`relay_*`、`adc_*`、`dsp_*`、`cal_*`、`meas_*`、`proto_*`、`ui_*`、`selftest_*`。
- 允许**新增**函数/字段；**修改已有签名/语义必须**：① 在提交里同时改 §3.4；② 发消息通知全体 owner；③ 保证所有调用点同批改完（一次提交内）。
- 结构体（`acq_cfg_t`、`adc_block_t`、`chan_spectrum_t`、`cal_record_t`、`meas_result_t`）的字段顺序/类型变更同样算破坏性变更。
- 模块内部 `static` 实现自由；头文件里不要放硬件地址以外的"魔法数"（常量集中在 `board_config.h`）。
- 中断/主循环边界：ISR 只做搬运与计数，**所有计算在主循环**；不要在 ISR 里 printf/浮点重活/malloc（本来也无 malloc）。

## 8. 编码规范（本工程专用）

1. C11，裸机，**无 malloc/heap**（`_sbrk` 软上限、堆 0）；不用可变长数组。
2. 只有 **float/double 数学**：测量链路用 `float`（`-fsingle-precision-constant` 可选）；**校准求解全程 `double`**（10 Ω 档相消需要 4.25 位十进制精度，见 §7.4）；禁止 `-ffast-math`（DFT 需确定性）。
3. 打印：只用整数/定点格式化（`results.c`）；`printf` 已重定向到 UART，但**不开** `-u_printf_float`；`nano` printf 不支持 `%lld/%llu`。
4. 时间/延时：`board_millis()`/`board_delay_ms()`；DWT 用于 µs 级；**忙等只在初始化**，测量用定时器+DMA。
5. 浮点结果不要和 0 直接比；相位归一化到 (−180°, 180°]；单位换算集中在 `results.c`。
6. 所有硬件常量（引脚、ARR、FREQREG、Rf 名义值、Flash 地址）集中在 `board_config.h` 或 §13.2 表对应位置，代码里不许散落魔数。
7. 错误处理：返回 `meas_err_t` 或 `int` 错误码，**禁止静默返回看似正常的数**（§3.7 硬规则）；诊断位见 §13.4。
8. 命名：模块前缀（`adc_`、`dsp_`、`cal_`…）；ISR 用 `*_isr`；静态函数用 `static`；文件级变量加模块前缀。
9. 提交前跑 `git diff` 自查：没有调试残留（printf 洪水、死循环、临时魔改）。

## 9. 验证协议（没有硬件也能推进）

三层验证（架构文档 §10.1）：

1. **离线金标准**（不需要板子）：Python + numpy 生成输入波形/期望复数结果 → `test/vectors/*.h`；板上 `test.c` 逐组比对，串口输出 PASS/FAIL。DFT、阻抗公式、校准闭式解都必须有向量。
2. **板级自检**（需要 DAPmini + 串口）：`SELFTEST` 10 项（时钟、DDS 幅度、α、开路、短路检测、Flash、OLED、UART、看门狗、DFT 一致性），输出 `boot_status` 位图。
3. **台架计量**（需要标准件）：标准电阻/电容/电感 vs 商用 LCR，记录 24 项验收数据（§10.5）。

数值改动纪律：改采样率/块长/窗口/校准模型后，用 `tools/verify/budget.py` 重算时序与噪声，并更新架构文档 §5/§9/§14.1；提交信息里写明"重算了哪些数"。

## 10. 已知坑与"别踩"清单

| 坑 | 现象 | 正确处理 |
|---|---|---|
| TIM8 是 16 位 | ARR+1=105000 写不进 | 用 TIM2（32 位），ARR=52499/5249/524/69 |
| ALIENTEK 风格"ADC 校准" | F4 头文件找不到 CAL 位 | 无软件校准，ADON+等待 tSTAB 即可 |
| DMA 访问 CCM | 传输静默失败 | 缓冲放 SRAM `.dma_buf`（32B 对齐、NOLOAD、KEEP） |
| 复位后 GPIO=Hi-Z | 上电瞬间继电器误吸合 | 固件最早期（SystemInit 后、main 前几行）配 PD0–PD6 输出低；建议硬件加 10 k 下拉 |
| 换档不静音 | I-V 开环、BUF634A 过冲 | 先 `dds_hold_reset` 静音 → 切档 → 解除静音 |
| 非 10 k 档只吸目标档 | 10 k（PD3）与目标档并联，Rf 错误 | 目标档 + PD3 继电器两只，顺序"先吸目标→断 PD3" |
| 100 Hz 1 s 预算 | 2 块就 1.28 s 超时 | 粗测 N≤128（推荐 64）、精测 K=1、950 ms 超时保护 |
| 10 pF 不校准 | 夹具 1 pF 杂散=10% 误差 | 先 `CAL O` 开路校准，夹具固定不动 |
| 电桥公式丢负号 | 相位差 180°、类型全错 | `Zx = −Zf_eff·(m1/m2)/α` |
| 电解电容判成电阻 | 类型识别错误 | 相角语义：C 的 φ 为负，\|φ\|<5.7° 才是 R |
| 中文路径/编码 | objcopy、脚本乱码 | 相对文件名、UTF-8 BOM、PYTHONIOENCODING=utf-8 |
| 多人同时改同一 docx | 无法合并 | 二进制文档同一时间只一个人改 |

## 11. AI Agent 工作方式要求（给"派活的人"看的）

- **一次只接一个任务**，任务里必须给：目标、写作用域（文件路径）、验收标准、相关架构文档章节号。
- Agent 开工后先在 `docs/软件任务板.md`（或 GitHub Issue）认领/写状态，避免撞车。
- Agent 的笔记和实验数据写 `DeepSeek/arch_notes/<agent-name>.md`（gitignore），**定稿结论才进 docs/**。
- Agent 提交前必须自检：build 两配置 exit 0、git diff 只含范围内的文件、没有把 `DeepSeek/`/build 产物加进暂存区。
- Agent 遇到"不确定但影响结论"的硬件问题：**停下来问**，不要编造；把问题记到架构文档 §12 的待确认清单。
- Agent 的最终回复格式建议：`做了什么 / 改了哪些文件 / 验证结果（命令+输出摘要）/ 未验证与风险 / 下一步建议`。
