# 网页上位机（串口读数 + 标定）需求与接口规范 v1.0

> 目标读者：负责实现网页上位机的人/AI。本文档只描述**需求与接口**，实现可自由选择技术细节。
> 固件侧协议 v1 需先落地（第 5 章），网页可按第 4 章的协议加 `?mock=1` 模拟数据先开发。

## 0. 一句话目标

浏览器网页通过 USB 串口连接电桥，**实时显示测量结果、控制测量、执行/保存校准、导出数据**；无服务端、单页、离线可用、中文界面。

## 1. 背景与现状

- 硬件：STM32F407 开发板 + 模拟前端；USART1（PA9=TX、PA10=RX）115200 8N1，接 USB-TTL 到 PC。
- 固件现状（截至 2026-11-25）：串口只有启动横幅 + 按键模拟命令（`1/2/b/d/s/?`），**没有测量结果输出**。
- 因此本规范包含两部分：**A. 固件串口协议 v1（必须新增）**、**B. 网页上位机功能与验收**。
- 测量链路已打通：1 kHz/1 kΩ 档、2 kΩ DUT 实测 |Z|=1996.9 Ω，单次重复性 σ≈1%。

## 2. 系统架构

```
电桥(USART1, 115200)
   └─ USB-TTL ──> PC
                    └─ 浏览器(Web Serial API) ──> 网页上位机（单页，无后端）
```

- 首选：**浏览器 Web Serial API**（Chrome/Edge 89+，需 `https://` 或 `http://localhost` 安全上下文）。
- 回退（Firefox/Safari 无 Web Serial）：提供一个可选 **Node 桥**（`serialport` → 本地 WebSocket），协议原样透传；网页自动检测，通过 `ws://127.0.0.1:<port>` 连接。
- 不做：云端、账号、数据库、远程访问。

## 3. 串口与接线

| 项 | 值 |
|---|---|
| 端口 | USART1：PA9(TX)→USB-TTL 的 RX，PA10(RX)→USB-TTL 的 TX，GND 共地 |
| 参数 | 115200 baud，8N1，无流控，无 RTS/DTR 要求 |
| 电平 | 3.3 V TTL（不要接 RS-232 电平） |
| 注意 | 板子 PA0=按键、PA1/PC0=模拟输入，USB-TTL 勿接到这些脚 |

## 4. 协议 v1（ASCII 行协议）

### 4.1 通用帧格式

```
$<TYPE>[,<field>...]*<XX>\r\n
```

- `$` 开始，`*XX` 结束；`XX` = **从 `$` 后到 `*` 前**所有字节的 XOR 校验（2 位大写十六进制）。
- 行最大 200 字节；`\r\n` 结束。校验错/未知 TYPE 的整行丢弃并计数（不要断开连接）。
- 所有数值为十进制整数，禁止科学计数法、禁止负数以外的符号；字段顺序固定，**未知字段追加在末尾**（向后兼容）。
- 单位：见 4.3；时间 `t_ms` 为设备开机毫秒（u32，可回绕）。

### 4.2 设备 → PC 帧

| TYPE | 格式 | 说明 |
|---|---|---|
| `BOOT` | `$BOOT,<proto>,<board_id>,<fw>,<fixture_id>,<cal_level>,<freq_cnt>,<range_cnt>*XX` | 上电/`?` 查询时发；proto=1；board_id 8 位 hex；fw 如 `0.4.0`；cal_level 0..4 |
| `RES` | `$RES,<seq>,<t_ms>,<freq_mhz>,<f_idx>,<range_idx>,<rf_mohm>,<status>,<cal_flags>,<diag>,<zmag_uohm>,<phi_mdeg>,<rs_uohm>,<xs_uohm>,<kind>,<value>,<unit>,<d_ppm>,<q_ppm>,<model>*XX` | 每次测量完成发一条 |
| `STATE` | `$STATE,<running>,<freq_mode>,<range_mode>,<model>,<cal_level>,<unsaved>*XX` | 状态变化时发（测量启停/模式切换/校准保存） |
| `CAL` | `$CAL,<kind>,<f_idx>,<range_idx>,<samples>,<done>,<err>*XX` | 校准进度；kind 1=CHANNEL 2=OPEN 3=STANDARD；done=1 表示该阶段结束；err=0 成功 |
| `CALRES` | `$CALRES,<kind>,<f_idx>,<range_idx>,<alpha_re_ppm>,<alpha_im_ppm>,<rf_mohm>,<cf_femto>,<zs_mag_uohm>,<zs_ph_mdeg>,<yo_siemens_nano>*XX` | 可选：每阶段完成后报摘要，供 UI 显示 |
| `MSG` | `$MSG,<text>*XX` | 人可读信息（如 `CAL SAVED` / `CRC VERIFIED`），UI 原样显示 |
| `ERR` | `$ERR,<code>,<text>*XX` | 错误；code 见 4.5 |
| `ACK` | `$ACK,<cmd>*XX` | 命令确认（可选，建议发） |
| `RAW` | `$RAW,<seq>,<count>,<bytes_hex>*XX` | 可选调试：原始 ADC 对（`count` 对，每对 4 字节 hex），默认关闭 |

`RES` 字段单位：

| 字段 | 编码 | 示例 |
|---|---|---|
| freq_mhz | 毫赫兹 u32 | 1 kHz = `1000000`；100 kHz = `100000000` |
| rf_mohm | 该档名义反馈电阻，毫欧 u32 | 1 kΩ = `1000000` |
| status | lcr_status 枚举 0..5（OK/BAD_INPUT/SINGULAR/CLIPPED/WEAK/NO_EXCITATION） | `0` |
| cal_flags | hex：bit0 CHANNEL、bit1 FEEDBACK、bit2 FIXTURE | `1` |
| diag | 8 位 hex（32 位诊断字，UI 原样显示） | `00000000` |
| zmag_uohm / rs_uohm / xs_uohm | 微欧 u64/i64 | 1996.932 Ω = `1996932000` |
| phi_mdeg | 毫度 i32 | −0.535° = `-535` |
| kind | 0=UNKNOWN 1=R 2=L 3=C | `1` |
| value | 主参数（带 unit）：unit=0 时单位 µΩ；unit=1 时单位 fF；unit=2 时单位 pH | C=1.592 µF → value=`1592000000`, unit=1 |
| unit | 0=Ω 1=F 2=H | `0` |
| d_ppm / q_ppm | 百万分之一（i64） | D=0.0093 → `9300` |
| model | 0=串联 1=并联 | `0` |

### 4.3 命令（PC → 设备，同样以 `\r\n` 结尾，无 `$` 与校验）

| 命令 | 作用 |
|---|---|
| `?` | 请求 BOOT 信息 |
| `PING` | 探活，回 `$ACK,PING` |
| `M` | 单次测量（相当于短按） |
| `C1` / `C0` | 连续测量 开/关 |
| `F<0..4>` | 频率模式：0=AUTO 1=100 Hz 2=1 kHz 3=10 kHz 4=100 kHz |
| `R<0..6>` | 量程模式：0=AUTO 1=10 Ω 2=100 Ω 3=1 kΩ 4=10 kΩ 5=100 kΩ 6=1 MΩ |
| `S<0\|1>` | 等效模型：0=串联 1=并联 |
| `CAL,CH` | 通道校准（α） |
| `CAL,OPEN` | 开路校准（夹具空载） |
| `CAL,STD,<ohm_uohm>` | 标准件校准；参数为标准件**真实阻抗**，单位 µΩ（例：1975.2 Ω = `1975200000`），范围 1 Ω–10 MΩ |
| `CAL,SAVE` | 保存校准到 Flash（双槽+CRC） |
| `CAL,CLEAR` | 清除校准（回名义值） |
| `CAL,ABORT` | 中止当前校准 |
| `RAW,0\|1` | 原始帧开关 |
| `RESET` | 软复位（APP 层，不拔电） |
| `H` | 帮助（回 `$MSG` 列表） |

### 4.4 时序与速率

- 单次测量约 **0.9–1.2 s**（1 kHz，8192 点、8 帧平均）；完成时发 1 条 `RES`。
- 连续模式每次完成发 `RES`；`STATE` 在状态变化时发。
- 上行约 150 B/条 × 1 Hz；115200 有大量余量。
- PC 端：发命令后 500 ms 无 `ACK`/`STATE` 则显示“未确认”；2 s 无任何帧显示“设备无响应”。

### 4.5 错误码（ERR.code）

| code | 含义 |
|---|---|
| 1 | CONFIG_ERROR |
| 2 | FRONTEND_ERROR |
| 3 | CAPTURE_ERROR |
| 4 | TIMEOUT |
| 5 | FRAME_ERROR |
| 6 | RANGE_LIMIT |
| 7 | USER_STOP |
| 8 | UNSTABLE |
| 9 | NO_EXCITATION |
| 10 | CAL_FAILED |
| 100 | PROTOCOL_ERROR（坏命令/参数越界） |
| 101 | CHECKSUM_ERROR |
| 102 | BUSY（校准/测量中拒绝新命令） |

### 4.6 示例

```
设备上电:
$BOOT,1,1A2B3C4D,0.4.0,1,1,4,6*5A

单次测量完成:
$RES,17,123456,1000000,1,2,1000000,0,1,00000000,1996932000,-535,1996857000,18653000,1,1996932000,0,9300,107500000,0*3F

校准进度:
$CAL,2,1,3,2,0,0*2B

保存完成:
$MSG,CAL SAVED / CRC VERIFIED*12

PC 命令:
F2
S1
CAL,STD,1975200000
```

> 校验：`$` 与 `*` 之间的字节逐字节 XOR；示例中的 `XX` 为占位，实现时以实际计算为准。

## 5. 固件侧改动清单（协议 v1 落地）

网页能跑起来的前提，按优先级：

### 5.1 新增 `firmware_next/src/lcr_protocol.c` + `include/lcr_protocol.h`

- 行接收缓冲 256 B（主循环轮询，不放在中断）；命令解析见 4.3。
- 发送：所有帧统一 `send_frame(type, fields...)`，最后追加 XOR；TX 走现有非阻塞 UART（512 B 缓冲，必要时自己排队）。
- 挂钩点：
  - `main()` 启动后发 `BOOT`；
  - `lcr_app_submit()`/测量完成 → 发 `RES`（从 `app.last` 格式化）；
  - 测量启停、模式切换、校准保存后 → 发 `STATE`；
  - 校准每组完成、阶段完成 → 发 `CAL`（`app.cal_*` 字段与 `app.session.kind`）；
  - 错误/提示 → `MSG`/`ERR`。

### 5.2 标准件校准支持（重要）

当前固件 RF STANDARD 用“名义 Rf”当标准值，不能输入真实值。需要：

- `lcr_app` 新增字段 `double cal_standard_ohm;`
- 新增接口 `int lcr_app_cal_start(lcr_app*, lcr_capture_kind kind, double standard_ohm, uint32_t now);`
- STANDARD 阶段改用 `zf = -standard_ohm * alpha / measured_ratio`（替换 `-Rf_nom*alpha/mean`），并校验 `|measured-standard|/standard < 2%`；
- 命令 `CAL,STD,<ohm_uohm>` 设置该值后再启动。

### 5.3 应用层 API（避免用按键事件模拟）

新增（键/网页共用）：
- `lcr_app_set_frequency_mode(app, mode)`、`lcr_app_set_range_mode(app, mode)`、`lcr_app_set_model(app, model)`；
- `lcr_app_start_once(app, now)`、`lcr_app_start_continuous(app, now)`、`lcr_app_stop(app)`；
- `lcr_app_cal_save(app)`、`lcr_app_cal_clear(app)`、`lcr_app_cal_abort(app)`；
- 查询：`lcr_app_state(app, ...)`（running/freq_mode/range_mode/model/cal_level/unsaved）。

### 5.4 格式化约束

- 固件未开 `-u_printf_float`：**禁止 `%f`**，全部用整数（µΩ、mdeg、mHz、ppm）自写除法/四舍五入格式化。
- 测量节拍不能被串口阻塞；长帧（8192 点）期间不要发大块数据。

## 6. 网页功能需求（FR）

- **FR-1 连接管理**：端口选择（Web Serial `navigator.serial.requestPort()`）、连接/断开、设备信息展示、断线提示与重连按钮；`?mock=1` 启用模拟设备（无需硬件）。
- **FR-2 实时读数卡**：大字显示 **|Z|** 与 **φ**；副参数显示 Rs/Xs（串联）或 Rp/Cp/Lp（并联，按 `model`）、主参数值+单位；显示频率、档位、校准等级、状态灯（OK/WEAK/CLIPPED/NO EXCITATION）；单位自动换算（Ω/kΩ/MΩ、pF/nF/µF、µH/mH/H）。
- **FR-3 控制面板**：单次测量、连续开关、频率 AUTO/100 Hz/1 kHz/10 kHz/100 kHz、量程 AUTO/6 档、串联/并联；命令发送后显示设备确认/超时。
- **FR-4 趋势图**：最近 600 个点的 |Z|（左轴）与 φ（右轴）双轴折线（Canvas 手绘，无第三方库）；暂停/继续、清空、鼠标游标读数。
- **FR-5 表格与导出**：每次 RES 追加一行（时间、频率、档位、|Z|、φ、Rs、Xs、kind、value+unit、D/Q、status、cal_flags）；导出 CSV（UTF-8 BOM，Excel 可开）与 JSON；一键清空。
- **FR-6 稳定性统计**：最近 N 个点（N=5/10/20/50 可选）的均值、σ、极差、相对 σ%；用于判断读数重复性。
- **FR-7 标定向导**：三步 **CHANNEL → OPEN → RF STANDARD → SAVE**：
  - CHANNEL：提示“断开 DUT，直接进入校准”（固件内部切换 K78 到 CAL 源）；
  - OPEN：提示“夹具保持空载”（已实测：裸夹具 V2 很小，多数档会被固件跳过，属正常）；
  - RF STANDARD：输入标准件真实值（Ω，1 Ω–10 MΩ，支持小数，内部转 µΩ），提示“接入标准件”；
  - 进度条由 `CAL` 帧驱动（kind/f_idx/range_idx/done）；完成后显示 `CALRES` 摘要（α、Rf、Cf）；提供 **SAVE CAL / CLEAR CAL** 二次确认；失败时显示 `ERR`/`MSG` 原文。
- **FR-8 诊断**：BOOT 信息、diag hex 展开为二进制、串口统计（收/发字节、坏帧数、校验错数、重连次数）、原始帧日志开关（可复制）。
- **FR-9 设置持久化**：端口、频率/量程/模型、N、主题存 `localStorage`；恢复默认按钮。
- **FR-10 主题与语言**：浅色/深色主题，中文默认，可切英文。

### 6.2 交互细节

- 连接成功后自动发 `?`，更新 BOOT/STATE；
- 连续模式：RES 到达即刷新，1 Hz 无闪烁（数字用等宽字体，避免布局跳动）；
- 命令按钮在设备 BUSY（校准中）时禁用并提示；
- 切换频率/量程后 1 s 内收到 STATE 才认为成功；
- mock 模式：1 Hz 生成符合协议的随机数据（含 WEAK 帧与偶尔一次 CAL 流程），供无硬件开发和演示。

## 7. 数据与导出格式

CSV 列（顺序固定）：

```
timestamp_iso,seq,t_ms,freq_hz,freq_index,range_index,rf_ohm,status,cal_flags,diag,
z_ohm,phi_deg,rs_ohm,xs_ohm,kind,value,unit,d,q,model
```

- `z_ohm` 等为浮点（由 µΩ/1e6 得到），保留 6 位小数；
- `timestamp_iso` 为 PC 收到帧的本地时间（ISO 8601 带时区）；
- JSON：`{"protocol":1,"boot":{...},"samples":[...]}`，字段名同上。
- 导出文件名：`LCR_YYYYMMDD_HHMMSS.csv/json`。

## 8. 非功能需求

- 浏览器：Chrome/Edge 89+（Web Serial）；Firefox/Safari 需 Node 桥；
- 离线：全部资源本地，**不引用 CDN**，一个目录拷贝即可用；
- 性能：10 Hz 刷新不丢帧，历史 ≥10k 点，内存 <200 MB；
- 可靠性：坏帧/校验错/断线不崩溃；断线重连；
- 可维护性：协议解析（纯函数）与 UI 分离，常量集中，含少量单元测试（可选 `node --test`）；
- 安全：不联网、无遥测、不申请多余权限（只需串口）。

## 9. 验收标准（AC）

- **AC-1** mock 与真实口均可连接；拔线后 2 s 内提示断线；
- **AC-2** mock 数据 1 s 内显示且单位换算正确：`1996932000 µΩ → 1.996932 kΩ`；`1592000000 fF → 1.592 µF`；`-535 mdeg → -0.535°`；
- **AC-3** 每个按钮命令都能看到 ACK/STATE 反馈；串口日志可见发送的命令与校验；
- **AC-4** 连续运行 10 min 无内存增长/卡顿，CSV 行数 = RES 数；
- **AC-5** 标定向导可用 mock 走完 CHANNEL/OPEN/STD/SAVE 四步，STANDARD 值校验（1 Ω..10 MΩ 拒绝越界）；
- **AC-6** 导出 CSV/JSON 与第 7 章字段一致，Excel/pandas 可打开，中文不乱码（UTF-8 BOM）；
- **AC-7** 伪造坏帧/校验错/ERR 帧：UI 提示且不影响后续数据；
- **AC-8** Windows 10/11 + Chrome/Edge + CP2102/CH340 USB-TTL 实测可用。

## 11. 实现提示（伪代码）

```js
// 校验
function xorSum(bytes) { let x = 0; for (const b of bytes) x ^= b; return x; }
function frame(type, fields = []) {
  const body = type + (fields.length ? ',' + fields.join(',') : '');
  const x = xorSum([...body].map(c => c.charCodeAt(0)));
  return '$' + body + '*' + x.toString(16).toUpperCase().padStart(2, '0') + '\r\n';
}
// 解析
function parseLine(line) {
  if (!line.startsWith('$')) return null;
  const star = line.lastIndexOf('*');
  if (star < 0) return null;
  const body = line.slice(1, star);
  const sum = parseInt(line.slice(star + 1, star + 3), 16);
  if (xorSum([...body].map(c => c.charCodeAt(0))) !== sum) return { type: 'BADCRC' };
  const f = body.split(',');
  return { type: f[0], fields: f.slice(1) };
}
```
