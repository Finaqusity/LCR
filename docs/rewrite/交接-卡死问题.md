## 2. 故障现象（精确描述）

1. 上电 / 按 RESET 后，继电器正常"咔哒"几次（约 2–4 次测量），屏幕短暂显示读数；
2. 然后**一切停住**：继电器不再响、OLED 冻结（最后停在 `AUTO` 状态）、串口无输出、按键无反应；
3. 只能按 RESET 恢复，恢复后仍然重复"几次测量 → 停住"；
4. **停住时 SWD 也连不上**：`pyocd` 报
   `Error while running debug sequence 'DebugDeviceUnlock' (core Cortex-M4): STLink error (20): DP wait`，
   但 `pyocd list --probes` 能看到探针（`37FF71064E5734364ECD1343`）。
   → 这个现象**很像是 MCU 进入了低功耗/停止模式**（STOP/STANDBY 下调试口无响应），
   或者主循环在 `__WFI()` 里等一个再也不会来的中断。
5. 拔掉 OLED 4 根线后症状不变（`响几下就不响了`）→ **不是 OLED 驱动卡死**。

## 5. 重点怀疑方向（供接手者参考）

1. **主循环 `__WFI()` 丢中断**：`firmware_next/platform/main.c:144` 每轮 `__WFI()`，靠 SysTick 唤醒。若某条路径把 SysTick 或全局中断关掉（或 `SysTick->CTRL` 被写坏），MCU 就会永久睡死，且表现正是"全停 + SWD 连不上"。
2. **`main.c` 里 `for (;;) { lcr_board_led(1); __WFI(); }` 的错误分支**（line 67/72/85/98）：如果新代码走进其中一个（例如启动检查失败），会表现为卡死 + 停止模式。建议在这些分支加串口打印确认。
3. **`cddd850` 的 `boot_grace` + 小电阻回 100 Hz 重测**：`result()` 扫描完成后若 `magnitude<50 Ω` 会把 `active_frequency` 改 0 再测一次，可能与 `scan` 状态互相触发。
4. **`8dcb332` 的 100 Hz 768 对 + `smooth_hist[5]`**：`lcr_app` 结构体变大，若有任何地方按旧偏移/旧数组长度访问（例如串口/校准代码里的手写偏移），会踩内存。
5. **`6eb84af` 的扫描跳过逻辑**：`++a->scan_index < 4u` 与 `next_start` 的组合，若某分支不推进状态，会让会话一直 SWITCHING（但那种情况按键应该还活着，与本故障不符）。

## 8. 已知硬件问题（别误判为软件）

1. **10 Ω 档（K2）驱动**：ULN2803 通道 1 损坏，用户改成 PD0/PD7 接三极管（NPN，1 kΩ 基极）低边驱动 K2 线圈；同时 K2 的 VO 引脚（pin4）与其它继电器 VO 网不通，已飞线补上。**固件 mask 仍是 `0x81`（PD0+PD7 同时置高），不要改**。
2. **K78（校准继电器）驱动**：ULN 通道 7 损坏，做 CHANNEL 校准需要用户临时把 K78 的 pin8 短接到 GND；RF STANDARD 校准不需要 K78。
3. **1 kΩ 档（r=2）读数不稳**（4959/4625/3640 之类乱跳），用户查过走线“正常”，原因未明——测评时尽量别用 1 kΩ 档。
4. **10 Ω 档 1 kHz/10 kHz 有 ±5% 双稳态**（V2 幅度 185↔197、残差 16↔26，settle 800→1000 ms 无效）；校准和测量要在同一状态里，优先用 100 Hz。
5. **DAC 后端不能出 100 kHz**：56 点正弦表 × 100 kHz = 5.6 MSPS，STM32F407 的 12 位 DAC 约 1 MSPS。100 kHz 只有 AD9833 后端能做（`-Ad9833` 构建）。
6. 测量节拍：100 Hz 目前 128 点（约 1.4 s/次）；`8dcb332` 已把它改成 768 点（480 ms 采集），但该提交在卡死版本里，未验证。
