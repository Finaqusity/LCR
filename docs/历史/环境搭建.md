# 开发环境搭建与使用（STM32F407 + DAPmini，全命令行）

> ⚠️ 已过时：现行开发环境说明见 [docs/开发环境.md](../开发环境.md)。本文仅作历史存档，内容可能失效。

> 目标：不用 Keil 点按钮，而是用 **CMake + Ninja + arm-none-eabi-gcc** 编译，用 **pyOCD（CMSIS-DAP）** 烧录调试。
> 这样 AI 助手能直接 `cmake --build`、`pyocd flash`、读串口、看反汇编，闭环不需要人点鼠标。

## 2. 一条命令编译

```powershell
cd D:\0-Documents\电子设计\电赛校队招新_测量题
powershell -ExecutionPolicy Bypass -File .\tools\build.ps1
```

产物在 `firmware\build\`：`lcr-fw`（ELF，调试用）、`lcr-fw.hex`、`lcr-fw.bin`。
`-Clean` 先清空；`-Release` 用 `-O2`。

当前基线（Debug）：text 17232 B / data 468 B / bss 628 B（+ heap/stack 1536 B），Flash 约占 17 KB。

手工等价命令：

```powershell
cmake -S firmware -B firmware/build -G Ninja `
      "-DCMAKE_BUILD_TYPE=Debug" `
      "-DCMAKE_TOOLCHAIN_FILE=$PWD\firmware\cmake\arm-none-eabi.cmake"
cmake --build firmware/build
```

> 注意：`-D...=$变量` 在 PowerShell 里必须整段加引号，否则 `$变量` 不会被展开（会原样传成 `$gen`）。

## 3. 烧录（DAPmini / CMSIS-DAP）

DAPmini 插 USB 后：

```powershell
pyocd list                     # 应看到一行 CMSIS-DAP
pyocd flash -t stm32f407vetx firmware\build\lcr-fw.hex --erase sector
pyocd reset  -t stm32f407vetx
```

或直接用 `tools\flash.ps1`（内部就是上面的命令）：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\flash.ps1
```

- 板子是 **STM32F407VET6** → 目标名 `stm32f407vetx`（512 KB Flash / 192 KB RAM）。
  如果是 VG 板子，改 `stm32f407vgtx`。
- 报 "no ack / target not found"：多半是供电或接线，见第 6 节。

## 4. 调试（GDB / VSCode）

```powershell
pyocd gdbserver -t stm32f407vetx --port 3333 --elf firmware\build\lcr-fw
# 另一个窗口
arm-none-eabi-gdb firmware\build\lcr-fw -ex "target remote :3333"
```

VSCode + Cortex-Debug 插件：

```json
{
  "type": "cortex-debug",
  "request": "launch",
  "name": "pyocd-f407",
  "servertype": "pyocd",
  "targetId": "stm32f407vetx",
  "cwd": "${workspaceFolder}",
  "executable": "${workspaceFolder}/firmware/build/lcr-fw"
}
```

## 5. 看串口（USART1：PA9=TX、PA10=RX，115200 8N1）

硬件：USB-TTL（CH340/CP2102）3.3 V 电平，TX/RX 交叉、**必须共地**，TX/RX 各串 100 Ω 更稳。

```powershell
python tools\monitor.py --list
python tools\monitor.py --port COM5 --log logs\uart.log
python tools\monitor.py --port COM5 --send "raw on" --duration 10
```

固件启动横幅：`# LCR fw=v0.1.0 build=...`，之后每 500 ms 一行 `$ tick=... ms=...`。

## 6. DAPmini 注意点

1. DAPmini = **CMSIS-DAP**，Windows 免驱（HID），pyOCD 原生支持，不需要 ST-Link 驱动。
2. 接线：`SWDIO`、`SWCLK`、`GND`（建议两根）、`3V3`（仅参考电平；板子单独供电时可悬空）、可选 `NRST`。
3. 排线尽量短（<15 cm）；跑飞了把速度降到 1 MHz（`tools\flash.ps1 -Speed 1000`）。
4. `pyocd list` 看不到设备：换 USB 口、换数据线（很多线只供电）、设备管理器里找 "CMSIS-DAP"。

## 8. 网络提示（本机实测）

- ARM 官方工具链：`developer.arm.com` 直连 403，但真实文件在 **`armkeil.blob.core.windows.net`**；单连接只有 ~45 KB/s，**16 路分块并发可到 ~4.5 MB/s**（见 `tools\_fetch_arm_gcc.ps1`）。
- pip 用 `-i https://mirrors.aliyun.com/pypi/simple`（官方源很慢、清华源 wheel 会 403）。
- GitHub release 用 `curl.exe -L` 能下（`Invoke-WebRequest` 会卡）。
- PlatformIO / xpack npm 包在本机不可用（403 或只是壳）；pyOCD 的 pack 索引与 pack 下载可用。

## 9. 踩过的坑（都已修好，改代码时别改回去）

| 现象 | 原因 | 已做的修复 |
|---|---|---|
| CMake 报 `not able to compile a simple test program`（`undefined reference to _exit`） | 裸机没有 syscalls，CMake 默认会链接测试程序 | 工具链文件加 `set(CMAKE_TRY_COMPILE_TARGET_TYPE STATIC_LIBRARY)` |
| `rules.ninja: expected newline, got lexing error`、cache 里 `CMAKE_BUILD_TYPE=$gen` | PowerShell 未展开 `-D...=$gen` | `build.ps1` 里参数整段加引号 |
| `attempt to rename spec 'link' to already defined spec 'nano_link'` | `-specs=nano.specs` 被加了两次 | 只在 `CMakeLists.txt` 里加一次，工具链文件不再加 |
| 链接成功但 `objcopy: No such file or directory`（路径乱码） | 中文目录 + cmd.exe 代码页 | POST_BUILD 全部用相对文件名（工作目录就是 build/） |
| PowerShell 脚本报 `Unexpected token`、中文乱码 | PS 5.1 把无 BOM 的 UTF-8 当 GBK | 所有 `.ps1` 存成 **UTF-8 with BOM** |
| 链接告警 `_close/_fstat/_isatty ... not implemented` | `nosys.specs` 的正常提示 | 可忽略 |
