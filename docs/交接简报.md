## 1. 这是什么项目

电赛校队招新测量题：**基于 STM32F407 的自动平衡电桥数字 RLC 表**。硬件已定稿并出了 Gerber（4 层 100×100 mm），现在写固件。

- 基础指标：100 Hz / 1 kHz / 10 kHz 正弦激励，0.5 Vrms，自动识别 R/L/C；R 10 Ω–100 kΩ ≤1%，C 1 nF–10 µF ≤2%，L 100 µH–100 mH ≤2%。
- 发挥项：加 100 kHz（C 100 pF–100 nF / L 10 µH–1 mH）、开短路校准后测 10 pF ≤5%、自动量程 ≥3 档（R 10 Ω–1 MΩ ≤0.5%）、单次 ≤1 s。
- 方案：DDS（AD9833）激励 + 运放 I-V 自动平衡电桥 + 双 ADC 同步采样 + 数字相干 DFT 取复比值；固件全裸机寄存器手写，**不用 HAL、不用集成阻抗芯片**。
- 现在进度：**软件架构 v1.0 已评审交付**（14 章），开发环境（VS Code / 工具链 / CubeMX 参考流程）已配好；固件处于 **M0 基础设施**起步（现有代码还是 Day1 骨架：LED 心跳 + 串口回显）。

## 2. 三分钟上手

```powershell
git clone https://github.com/Finaqusity/LCR.git
cd LCR

# 编译（Debug，产物 firmware/build/lcr-fw.elf/.hex/.bin）
powershell -ExecutionPolicy Bypass -File tools\build.ps1

# 插上 DAPmini 后烧录 + 复位
powershell -ExecutionPolicy Bypass -File tools\flash.ps1

# 串口（115200 8N1；绕开 Windows Store 的 python 别名）
powershell -ExecutionPolicy Bypass -File tools\monitor.ps1 --port COMx
```

工具链不在 PATH，若 `build.ps1` 报找不到 cmake/gcc，先看 [`开发环境.md`](开发环境.md) §1；VS Code 装三个扩展（C/C++、CMake Tools、Cortex-Debug）后 `Ctrl+Shift+B` 编译、`F5` 下载调试。

## 4. 红线：这些数值是定稿，写码时不许“改回文档旧值”

| # | 定稿 | 旧值/易错点 |
|---|---|---|
| 1 | ADC 时钟 **21 MHz**（PCLK2 /4） | 硬件接口.md 写 28 MHz，F407 分频器做不到 |
| 2 | 采样 **S=fs/f0 = 16/16/16/12**（100 kHz 用 S=12，fs=1.2 MSPS） | 旧文档 fs=16·f0 全场 |
| 3 | 触发 **TIM2_TRGO，EXTSEL=0b0110**（TIM2 PSC=0，ARR=52499/5249/524/104） | TIM8 是 16 位、装不下 105000；EXTSEL=1110 也不对 |
| 4 | DFT：先做 S 相累加（每样本 1 次整数加法）再 S 点 DFT，N=1024（100 kHz N=1008） | 别用 1024 点朴素 DFT |
| 5 | 母公式 **Zx = −Zf_eff·(m1/m2)/α**（除 α，不是乘） | 硬件接口.md/旧图写乘 α，会差 α² |
| 6 | **无短路校准**（0.5 Vrms 下 0.1 Ω = 5 A，会烧 10 Ω 档 Rf）→ 用**双负载两点法** | 旧文档的“短路校准”不可执行 |
| 7 | 类型判据 **\|φ\|<5.7°→R**；电容 φ 为负 | 旧 10° 会误判电解电容 |
| 8 | 1 MΩ 档 **禁止 100 kHz**（1 M∥2.2 pF 误差 −41%），10 kHz 仅校准后可用 | — |
| 9 | 代码区 **256 KB**（FLASH LENGTH=256K），校准区 sector6+sector7 双扇区各 128 KB；`cal_blob_t v2=1240 B`、槽 1536 B、CRC32+seq | 旧值 384/512 KB、0x0807F000 单页 |
| 10 | DMA 缓冲放 **SRAM**，绝不能进 CCM；栈也在 SRAM | F4 DMA 访问不到 CCM |
| 11 | 10 Ω 档短路会烧 Rf：削顶/过流必须**立即静音 + 降档**；换档要“先吸目标档再断 K48” | — |
| 12 | 非 10 k 档要 **2 只继电器同时吸合**（目标档 + K48，约 42 mA）；复位到 GPIO 初始化窗口可能误吸合，固件最早期配输出低 | “同时只许一只”是旧描述 |
| 13 | 100 Hz 档 K=1 块（0.64 s），100 kHz ≤105 ms；粗测用 N=64 | 否则超 1 s |
| 14 | **不用浮点 printf**（固定格式化）、不 `malloc`、不开 `-ffast-math` | 体积/确定性 |
| 15 | 本机无 host 编译器：单测走 **numpy 金标准向量 + 板上 selftest** | 别写 x86 单测 |

> 其余 12 项“待实物确认”的硬件细节（VR1/Cc 实际值、ULN COM 下拉、SPI 模式、K 编号等）见架构文档 §12，**不要编造**。

## 5. 现在能接什么活

任务板 [docs/软件任务板.md](软件任务板.md) 里每行有：写作用域、依据章节、验收标准、依赖、状态、owner。规则：**认领前先读对应架构章节**；在群里说一声“我领 M0-1”，把状态改成“进行中(名字)”；完成后填 commit 短哈希并打 `完成`。

当前里程碑 **M0（基础设施）**，可并行：

- **M0-1** 时钟/系统初始化：`board.c` —— HSE→PLL 168/84/42/21 MHz、MCO1=HSE/1、PC13 心跳、HSE 失败回退、DWT、SysTick 1 ms。
- **M0-2** 链接脚本与构建：`STM32F407VETx_FLASH.ld` 改 256K + `.dma_buf` + `.ccmram` + `__StackLimit` + 双 ASSERT；CMake 加 `-Wdouble-promotion`、去掉浮点 printf、`syscalls.c`、`tools/check_map.py`。
- **M0-3** 测试设施：numpy 生成 12 组金标准向量 `test/vectors/*.h` + 板上 `TEST` 命令。

之后 M1（DDS/继电器）→ M2（ADC+DMA/折叠 DFT/自检）→ M3（测量状态机/串口/校准/OLED）。**M0 不过门槛不进 M1**。

## 6. 协作规则（简版）

- **分支**：小改动可直接 `master`；功能任务开 `feat/M0-1-clock` 这类分支，群里`@Lead` 做 review 后合。**禁止 force push**。
- **提交信息**：`type(scope): 中文描述`，type ∈ feat/fix/docs/chore/test；一次提交一件事。
- **DoD（完成定义）**：`tools\build.ps1` 与 `-Release` 都 **0 warning**；自己跑的验收项过；更新任务板行；文档改动同步架构文档对应节。
- **写作用域**：一个文件同一时间只有一个人改；要动别人的文件先在群里说。笔记/临时脚本放 `DeepSeek/arch_notes/`（已 gitignore），别提交 `build/`、`_ds/`、`DeepSeek/`。
- **数值改动**：改采样率/块长/校准模型后必须用 `tools/verify/budget.py` 重算时序与误差（断言 0 失败才算数），并在提交信息写明“重算了哪些数”。
- **提问**：先 `grep` 架构文档/交接说明；仍不确定的硬件问题列到架构文档 §12 的开放项，不要凭猜写代码。

## 8. 常见坑（撞了先看这里）

1. `python` 是 Windows Store 占位别名 → 用 `tools\monitor.ps1` 或真实解释器 `C:\Users\Finaqusity\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe`。
2. 构建报 `CMake Error` 且与中文路径相关 → 产物路径别放进含中文的目录；objcopy 用相对名（已配好）。
3. pyocd 说 `No available debug probes` → DAPmini 没插好/驱动异常/BOOT0 被拉高。
4. 烧完不跑 → 查 BOOT0 低、复位、供电；串口无输出先查串口线序（PA9/PA10 交叉）与 115200。
5. 中断里做 DFT/打印 → 绝对禁止；DMA 半满/全满只搬运，DFT 在主循环。
6. 改 `.ioc`/CubeMX 生成：只作参考，输出路径必须纯 ASCII，外设只能在 GUI 配（详见开发环境 §6.1.1）。
7. 本仓库 `.ps1` 必须存成 **UTF-8 with BOM**。
