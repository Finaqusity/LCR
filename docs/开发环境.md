## 6. STM32CubeMX 怎么用（推荐：只当"配置仪表盘"）

**结论：CubeMX + VS Code 很方便，但本项目不要让 CubeMX 托管工程**。原因：
- 时序关键路径（ADC1/2 双规则同步 + TIM2 TRGO + DMA、折叠 DFT、继电器互锁/静音、校准）是手写寄存器 + 裸机；HAL 生成的初始化会把这些重新包一层，还要按架构文档 §14.1 改回 21 MHz ADC、S=16/12、TIM2_TRGO 等定稿值。
- 已评审的驱动设计（架构文档 §4）与 HAL 的寄存器写法一一对应，CubeMX 的价值是**图形化校验时钟树/Pinout、对照生成的 `SystemClock_Config()`/`HAL_*_MspInit()` 抄寄存器值**，而不是产物。

UM1718 里可脚本化的命令只有：`load / loadboard / config load|save|saveext|saveas / csv pinout / project name|path|toolchain|compiler|generate / set tpl_path|dest_path / get / script / SetStructure / SetCopyLibrary / generate code / login / exit`。**没有配置外设模式的命令**，所以 §6.2 的 Pinout 与时钟树必须在 GUI 里点。

实测限制（三处坑，别踩）：

1. **路径必须纯 ASCII**：`-OutDir` 或 .ioc 路径含中文时，CubeMX 会回退到 .ioc 所在目录生成，并可能弹出 `Save Project As` 模态框——headless 没人点，只能杀进程。`tools\cubemx.ps1 -Gen` 会提前拒绝非 ASCII 路径。
2. **.ioc 必须先在 GUI 里配到"能生成"**：如果时钟树不自洽（典型：只写了 PLL 参数、漏了 APB1 分频），日志会出现 `IP not ready for code generation: Clock`，CubeMX 弹出 `Warning: Code Generation ... [Clock]` 模态框等人工点 Yes/No。脚本检测到该行会立刻中止并提示去 GUI 里点 PCC 面板的 "Solve"。
3. **别手改 .ioc 的时钟键**：`D:\Tools\lcr-cubemx` 里 11 月 10 日留下的 `lcr-full.ioc` 是手写残文件（缺 HSE/分频/外设参数），CubeMX 会静默丢掉 ADC/SPI/TIM/USART 并回落到默认时钟（PCLK1=168 MHz 超限）。正确做法是以 GUI 里重新配好的 .ioc 为唯一来源；值得留痕的 .ioc（约 5 KB）可提交到 `docs/cubemx/`。

### 6.2 建议流程（生成到 gitignore 的参考目录）

1. `File → New Project`，选 **STM32F407VETx**。
2. 按 `docs/硬件接口.md` 摆配置（要点）：
   - **RCC**：HSE = Crystal/Ceramic Resonator；时钟树 SYSCLK 168 MHz、APB1 42、APB2 84；ADC 预分频 **/4 → 21 MHz**（CubeMX 显示 PCLK2/4，不是 /8、也不是 28 MHz）。
   - **GPIO**：PD0–PD6 输出低；PC13 LED；PA4 推挽输出（FSYNC，默认高）；PA8 复用 MCO1（CubeMX 可能不暴露 MCO1 选项，需手写 `RCC->CFGR`）。
   - **SPI1**：16-bit、MSB first、Mode 1（CPOL=0/CPHA=1）、软件 NSS（NSS 由 PA4 手控）。
   - **USART1**：115200 8N1；**I2C1**：400 kHz（OLED）。
   - **ADC1/2**：双规则同步（ADC1 主、ADC2 从，Multi mode = Regular Simultaneous）；DMA2 Stream0 Channel0、Circular、32-bit；触发源 **TIM2 TRGO**（EXTSEL=0110，EXTEN=01 上升沿）；Sampling Time = 3 cycles。
   - **TIM2**：PSC=0、MMS=Update；ARR 按频点 52499 / 5249 / 524 / 104（Q 值 52500/5250/525/105）。
   - **NVIC**：优先级按架构文档 §3.6（DMA > USART > SysTick）。
3. `Project Manager → Toolchain/IDE = CMake`。注意输出路径必须纯 ASCII（例如 `D:\Tools\lcr-cubemx\out`），**不要**直接生成到本仓库（`D:\0-Documents\...` 含中文会失败，见 §6.1.1）；需要对照的文件再手动拷到 `firmware/_cubemx/`（已在 `.gitignore`，**不要**加进产品 `CMakeLists.txt`）。
4. 把生成的 `Core/Src/main.c`、`stm32f4xx_hal_msp.c`、`SystemClock_Config()` 当"参考答案"：对照 `Core/Src/board.c`、`dds.c`、`adc.c` 的寄存器配置；值不一致时以架构文档 §14.1 为准。
5. 想留痕：把 `.ioc` 复制到 `docs/`（纯 XML，几十 KB）或提 issue 说明，**生成的 C 代码不要入库**。

### 6.3 什么时候才考虑"CubeMX 全托管 + HAL"

仅当换上更复杂的方案、对周期抖动不敏感时。代价：§4 驱动设计全部重写、`F407` 的 HAL 多 ADC DMA 路径要重新验证、§9/§10 的时间与误差预算全部复算、二进制明显变大。本项目（比赛、已评审架构）**不推荐**。

## 7. 构建系统里已经踩过的坑（改 CMake 前必读）

1. **必须加** `set(CMAKE_TRY_COMPILE_TARGET_TYPE STATIC_LIBRARY)`（否则 CMake 链接测试程序报 `undefined reference to _exit/_close/_sbrk`）。
2. PowerShell 里 `-DCMAKE_BUILD_TYPE=$gen` **必须整段加引号**：`"-DCMAKE_BUILD_TYPE=$gen"`，否则 cache 里写进字面量 `$gen`，ninja 报 `expected newline`。
3. `-specs=nano.specs` **只能加一次**（重复会 `attempt to rename spec 'link'`）。
4. POST_BUILD 的 objcopy 用**相对文件名** `$<TARGET_FILE_NAME:lcr-fw>`（绝对中文路径经 cmd 会乱码）。
5. 所有 `.ps1` 必须存成 **UTF-8 with BOM**（Windows PowerShell 5.1 会把无 BOM 的 UTF-8 当 GBK，报 `Unexpected token`）。
6. 链接时出现 `_close/_lseek/_read` 等 warning 是 `-specs=nosys.specs` 的正常现象，忽略即可。
7. ELF 默认无扩展名，已在 `CMakeLists.txt` 里 `set_target_properties(... SUFFIX ".elf")` 生成 `lcr-fw.elf`；改输出名时同步 `launch.json`、`tools/*.ps1`、`docs`。
8. CubeMX 的 headless 生成输出目录必须纯 ASCII（本仓库路径含中文）；中文路径会回退目录并弹 `Save Project As` 模态框，详见 §6.1.1。

## 8. 烧录/调试常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| `pyocd list` 显示 "No available debug probes" | DAPmini 没插/驱动异常 | 换 USB 口；设备管理器看有无 `CMSIS-DAP` |
| `No ACK received` / 连接失败 | SWD 线序错或目标没供电 | 检查 SWDIO/SWCLK/GND/3V3 四根；先给板子上电 |
| 烧录后不运行 | BOOT0 被拉高 | 把 BOOT0 跳线拨回低电平，复位 |
| `pyocd flash` 报 unknown target | 器件包没装 | `pyocd pack install stm32f407vetx` |
| 串口无输出 | CH340 未识别 / 波特率 | 装 CH340 驱动；确认 115200 8N1；PA9/PA10 交叉 |
| 编译报 `arm-none-eabi-gcc not found` | 脚本没找到工具链 | 检查 `D:\Tools\embedded\arm-gcc-14.2\bin` 是否存在 |
| VS Code F5 报 `gdb not found` | gcc 路径不对 | 改 `launch.json` 的 `armToolchainPath` |
| 终端里 `python` 提示 "Python was not found" | PATH 命中 Windows Store 别名 | 用 `tools\monitor.ps1`，或写真实解释器绝对路径（§1） |
| 改完 CMake 但 IntelliSense 不更新 | 没重新编译 | 跑一次 `build (Debug)` 生成 `compile_commands.json` |

## 9. 固件分层（以架构文档为准）

目录树、13 个模块职责、C API 契约见 [docs/软件架构.md](软件架构.md) §3.2–§3.4；本节只列最常用的头文件：

```

  board_config.h   # 全部硬件常量（引脚/档位/频率表）集中处
```

`main.c` 只做：初始化 → 自检 → 串口/OLED 命令循环；禁止在 ISR 里做 DFT 或打印。
